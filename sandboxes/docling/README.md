# Docling Sandbox Prototype

Status: **experimental, isolated, not wired into MIZAN**. Nothing in this folder
touches MIZAN's main repository or any production system.

## Purpose

Evaluate whether [Docling](https://github.com/docling-project/docling) is a
viable **Document Intelligence / Universal Intake** layer for MIZAN, using only
synthetic, non-sensitive data. This is a sandbox, not a replacement for MIZAN's
existing systems.

See the root-level evaluation already on file before reading further:
[`../../evaluations/docling.md`](../../evaluations/docling.md).

## Safety rules followed in this sandbox

1. No real case files, personal data, or legal documents were used anywhere.
   Every fixture in `fixtures/` is synthetic, invented text generated by
   `fixtures/generate_fixtures.py` (born-digital) and
   `fixtures/generate_scanned_corpus.py` (raster/scanned, no text layer),
   clearly labeled "NOT A REAL CASE FILE".
2. No MIZAN production code or repository was modified.
3. All dependencies are installed into an isolated virtual environment
   (`.venv/`, not committed) inside this sandbox folder only.
4. Extraction results are never treated as verified facts — see
   [`adapter.py`](adapter.py) docstring for the
   `SOURCE → RAW EXTRACTION → NORMALIZATION → INTERPRETATION → VERIFICATION → ACCEPTED FACT`
   separation this prototype enforces. The adapter only ever produces RAW
   EXTRACTION (`raw_text`) and NORMALIZATION (`normalized_text`) output.

## Structure

| Path | Purpose |
|---|---|
| `adapter.py` | `DoclingAdapter` — the only code that imports `docling` directly. Performs real OCR routing (born-digital/scanned/ambiguous) and NFKC normalization internally; everything else should depend on `NormalizedDocumentResult`, not on Docling. |
| `requirements.txt` | Pinned sandbox dependencies |
| `fixtures/generate_fixtures.py` | Generates born-digital synthetic fixtures (PDF, DOCX, XLSX, PPTX, Arabic, mixed-language, corrupted, unsupported) |
| `fixtures/generate_scanned_corpus.py` | Generates 5 fully-raster (zero text layer) synthetic scanned Arabic PDFs + ground-truth `.expected.txt` files, for real OCR testing |
| `fixtures/*` | Generated synthetic fixtures (regeneratable, not hand-authored binary blobs) |
| `tests/test_docling_adapter.py` | Core adapter behavior: read success, raw/normalized text fidelity, table extraction, ordering, error handling, determinism, performance, provenance |
| `tests/test_ocr_routing.py` | Proves OCR routing is real: born-digital→OCR off, scanned→OCR on, ambiguous→OCR on + warning, decision recorded in the result |
| `tests/test_scanned_ocr_quality.py` | Runs OCR on the scanned Arabic corpus and computes/records CER/WER against ground truth (not just `success=True`) |
| `tests/test_windows_stability.py` | Repeated/sequential/bounded-concurrent run probes for the Windows access-violation investigation |
| `tests/test_offline_local_first.py` | Verifies conversions (including OCR) succeed in a subprocess with network/hub access explicitly disabled, once models are cached |
| `benchmark/ocr_metrics.py` | Dependency-free Levenshtein-based CER/WER implementation |
| `benchmark/benchmark_cold_warm.py` | Standalone script separating cold-start (adapter construction) from warm processing (repeated conversions) timing |
| `benchmark/RESULTS.md` | Actual measured results: format support, Arabic/NFKC finding, OCR routing, the Arabic-OCR-language critical finding, CER/WER, cold/warm benchmarks, Windows stability investigation, offline verification |
| `benchmark/ocr_quality_results.json` | Reproducible raw data backing the CER/WER table (expected text, extracted text, scores per case) |
| `benchmark/cold_warm_results.json` | Reproducible raw data backing the cold/warm benchmark table |
| `COMPARISON_AND_DECISION.md` | Final REUSE/EXTEND/CONNECT/INSPIRE/REJECT decision with reasoning |

## How to reproduce

```powershell
cd sandboxes\docling
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
.\.venv\Scripts\python fixtures\generate_fixtures.py
.\.venv\Scripts\python fixtures\generate_scanned_corpus.py
.\.venv\Scripts\python -m pytest tests -v
.\.venv\Scripts\python benchmark\benchmark_cold_warm.py
```

First run will download OCR/layout models from the internet (RapidOCR weights
from `modelscope.cn`, including an Arabic-language recognition model, and a
layout model from the Hugging Face Hub — see `benchmark/RESULTS.md` §9 for
exact cache locations); this requires network access once, subsequent runs
are cached locally and were verified to work fully offline
(`tests/test_offline_local_first.py`).

## Headline results (Revision 2 — see `benchmark/RESULTS.md` for full detail)

- 49 automated tests collected; **47 passed, 2 failed** in the most recent
  full run. Both failures are genuine, documented negative results, not
  hidden or worked around:
  - `test_scanned_ocr_quality.py::...scanned_arabic_table` — OCR word-error
    rate (1.524) exceeds even the loose sanity ceiling for the Arabic-table
    scan case.
  - `test_windows_stability.py::test_investigation_finding_is_documented` —
    gates on the Windows investigation write-up being present (this file
    satisfies it once committed).
- **Critical finding**: Docling's default OCR configuration uses
  `lang=['ch']` (Chinese) and silently fails on Arabic script — either
  producing garbage or silently dropping Arabic text while keeping
  English/numeric content intact. This sandbox's adapter now explicitly
  configures `lang=["arabic","en"]`, which fixes the silent failure but still
  yields poor quality (CER 36%–100%, WER 43%–152% across 5 synthetic scanned
  cases) — **not production-usable for legal documents as-is**.
- NFKC normalization is now enforced **inside the adapter**, not as a
  test-only workaround, with `raw_text` preserved separately for
  provenance/audit.
- OCR routing (born-digital/scanned/ambiguous) is implemented in code and
  tested, not just described.
- The Windows `access violation` signal was investigated, not dismissed:
  classified `UNRESOLVED`, with evidence pointing at Docling's native
  `docling_parse` backend.
- Offline/local-first operation (including OCR) was verified to work once
  models are cached, with exact cache locations documented for
  pre-provisioning an air-gapped deployment.

## Final decision

See [`COMPARISON_AND_DECISION.md`](COMPARISON_AND_DECISION.md) for the full
reasoning. Headline decision: **EXTEND** — Docling is adopted as an isolated,
adapter-wrapped ingestion capability for **born-digital** documents across the
5 tested formats, with mandatory NFKC normalization and explicit OCR routing
implemented by MIZAN's adapter, not accepted as-is. **Scanned Arabic OCR
quality and the Windows stability question are explicitly NOT yet production
ready** — see the comparison document for required next steps. The claim that
nothing in this sandbox overlaps with MIZAN's existing ingestion has been
withdrawn; that comparison has not actually been performed (`NEEDS COMPARISON
WITH CURRENT MIZAN INGESTION`).
